# Cassette Format and CLI Reference

`.agentrun.json` files are serialized `AgentRun` objects. They are written by `Recorder.save(...)`, loaded by `load_run(...)`, consumed by `ReplayEngine`, and inspected by the `agentcontract` CLI.

## Top-Level Structure

```json
{
  "schema_version": "1.0.0",
  "run_id": "uuid",
  "source": {
    "recorded_at": "2026-01-01T12:00:00+00:00",
    "recorder_version": "0.1.0",
    "sdk": "agentcontract-python"
  },
  "model": {
    "provider": "openai",
    "model": "gpt-4o",
    "temperature": 0.0,
    "top_p": 1.0,
    "max_tokens": 4096,
    "seed": 42
  },
  "metadata": {
    "scenario": "refund-eligible",
    "tags": [],
    "description": ""
  },
  "summary": {
    "total_turns": 4,
    "total_duration_ms": 1234.5,
    "total_tokens": {
      "prompt": 120,
      "completion": 45,
      "total": 165
    },
    "total_tool_calls": 2,
    "estimated_cost_usd": 0.0
  },
  "turns": []
}
```

## Top-Level Fields

### `schema_version`

Cassette schema version string. The current default is `"1.0.0"`.

### `run_id`

Unique run identifier generated by `Recorder`.

### `source`

Recording metadata.

- `recorded_at`: ISO 8601 timestamp string
- `recorder_version`: package version used to record the run
- `sdk`: SDK identifier, default `"agentcontract-python"`

### `model`

Model settings captured with the run.

- `provider`
- `model`
- `temperature`
- `top_p`
- `max_tokens`
- `seed`

These fields are present even if some values are empty or defaulted.

### `metadata`

User-level scenario metadata.

- `scenario`: scenario name used by the plugin and CLI
- `tags`: list of strings
- `description`: freeform string

### `summary`

Run totals.

- `total_turns`
- `total_duration_ms`
- `total_tokens.prompt`
- `total_tokens.completion`
- `total_tokens.total`
- `total_tool_calls`
- `estimated_cost_usd`

`Recorder.recording()` populates turn count, duration, token totals, and tool-call totals when the recording context exits.

### `turns`

Ordered list of conversation turns.

## Turn Objects

Each turn contains:

- `index`: integer turn index
- `role`: one of `system`, `user`, `assistant`, or `tool`
- `content`: optional string
- `tool_calls`: optional list
- `timing`: optional object
- `tokens`: optional object

Example:

```json
{
  "index": 1,
  "role": "assistant",
  "content": "Checking your order.",
  "tool_calls": [
    {
      "id": "tc1",
      "function": "lookup_order",
      "arguments": {"order_id": "123"},
      "result": {"status": "delivered"},
      "duration_ms": 18.5
    }
  ],
  "timing": {
    "latency_ms": 220.0,
    "time_to_first_token_ms": null
  },
  "tokens": {
    "prompt": 40,
    "completion": 12,
    "total": 52
  }
}
```

## Tool Call Fields

Each `tool_calls[]` entry contains:

- `id`: string identifier
- `function`: tool/function name
- `arguments`: JSON object
- `result`: any JSON-compatible value
- `duration_ms`: optional float

During serialization, non-JSON payloads are normalized:

- `Path` becomes a string
- objects with `isoformat()` become ISO strings
- sets become sorted lists
- any other unsupported value falls back to `str(value)`

During deserialization:

- missing object sections become empty objects
- missing array sections become empty arrays
- non-object `arguments` values become `{}`
- non-string `content` values are coerced to strings
- invalid or missing `role` values raise a `ValueError`

## Replay Model

`ReplayEngine` reads the cassette and exposes:

- `recorded_run`: the original `AgentRun`
- `tool_stub.get_result(function, arguments=None)`: recorded tool results in call order
- `tool_stub.has_results(function)`: whether more recorded calls remain
- `finish(actual_turns=None)`: mismatch accounting against actual replayed turns

Argument matching is strict when you pass `arguments` to `get_result(...)`. If the next recorded tool call for that function does not match, replay raises `ToolStubArgumentsMismatch` and does not consume the recorded call.

## CLI Commands

### `agentcontract info PATH`

Loads a cassette and prints:

- scenario
- run ID
- recorded timestamp
- `provider/model`
- total turns
- total tool calls
- total duration in milliseconds
- total tokens
- estimated cost

It exits with status `1` if the file is missing or cannot be parsed.

### `agentcontract validate PATH`

Loads a cassette and prints a success line with the scenario name and turn count. It exits with status `1` if the file is missing or invalid.

### `agentcontract init`

Writes a starter `agentcontract.yml` in the current directory. It exits with status `1` if the file already exists or cannot be written.

The starter file includes:

- `scenarios.include`
- `replay.stub_tools`
- `replay.concurrency`
- one example `defaults.assertions` entry
- one example `tool_allowlist` policy
- minimal `budgets` and `reporting` sections

## Relationship Between Cassettes and CLI

- `agentcontract info` and `agentcontract validate` are read-only views over `.agentrun.json`.
- `agentcontract init` does not touch cassettes; it only creates `agentcontract.yml`.
- The pytest plugin records and replays by scenario name, using `<scenario>.agentrun.json` under the configured scenarios directory.
